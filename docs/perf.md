# 性能记录

测量环境：Windows，主屏 2048×1280 DIP @125%（2560×1600 物理像素）+ 副屏，Electron 45.1.0。
数据来自 `npm run selftest`（`app.getAppMetrics()`，所有进程合计）。

## 内存（私有字节，所有进程合计）

| 状态 | 软件渲染（默认） | GPU 加速 |
|---|---|---|
| 只有托盘（菜单收起） | **71 MB** | 212 MB |
| 悬浮菜单 | 92 MB | 189 MB |
| 菜单展开 | 104 MB | — |
| 标注画布打开 | 185 MB | 502~562 MB |
| 光标特效开启 | 163 MB | 539~660 MB |
| Agent 面板 | 138 MB | 274 MB |

GPU 模式下多出来的几乎全在 GPU 进程（全屏透明窗口的合成表面）。这个应用每帧要画的东西很少，
软件渲染完全够用，所以**默认关闭 GPU 加速**，托盘里可以打开（会重启）。

## CPU（所有进程合计，占一个核的百分比）

| 场景 | 软件渲染 |
|---|---|
| 菜单空闲 | 0 % |
| 托盘待机 | 0 % |
| 特效开着、光标静止 | 0 % |
| 60 Hz 画笔拖动 | 1.5~3 % |
| 60 Hz 光标移动（聚光灯 + 激光笔） | 2~4 % |

## 做了什么

- **窗口按需创建，关掉即销毁**：菜单收进托盘是 `destroy()` 不是 `hide()`；画布、特效层、Agent 面板同理。
- **默认软件渲染**（见上表）。
- **零帧空闲**：菜单呼吸动画 6 秒无操作后暂停；画布只在内容变化时重画，"自动淡出"在保持期用定时器而不是 rAF 空转；特效层光标不动就不画。
- **脏矩形**：特效层只重画光标附近一块，聚光灯的暗幕在洞外不变，不重填整屏。坐标按设备像素对齐，避免 125% 缩放下的接缝。
- **自适应轮询**：光标在动 60 Hz、静止 300 ms 后降到 15 Hz；只开"晃动放大"时检测在主进程做，没晃就不发 IPC。
- 激光拖尾用"宽淡 + 细亮"两遍描边代替 `shadowBlur`（模糊在软件渲染下最贵）。
- 无前端框架、图标内联 SVG、唯一运行时依赖 `perfect-freehand`（约 2 KB）。
- 关闭 Chromium 用不到的功能：媒体键、翻译、组件更新、后台网络等；`spellcheck:false`。
- 设置写盘 400 ms 去抖。

## 还能再压的地方

- 托盘待机 71 MB 里，Browser 进程约 43 MB、GPU 进程（软件合成）约 17 MB、网络服务约 12 MB，这是 Electron 的底座，应用层基本没有可削的了。再往下只能换 Tauri / 原生。
- 打包时用 `electronLanguages` 只保留中英文，减小安装包体积（不影响运行内存）。
